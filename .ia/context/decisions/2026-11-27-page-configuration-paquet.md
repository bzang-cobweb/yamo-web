# `2026-11-27` — Page « Configuration » par un paquet local, cœur indépendant de Filament

- **Type** : décision
- **Question posée** : « écrire un package laravel filament qui permet de voir et consulter la config même celle des modules. bien structurer afin que la base puisse facilement s'adapter à autre chose que filament. Tous les commentaires en anglais ».
- **Réponse** : paquet local `packages/config-viewer` (`bza/laravel-config-viewer`, dépôt composer `path` sur `packages/*`). Un cœur sans Filament (`ConfigInspector`, sources `ApplicationConfigSource` et `ModuleConfigSource`, masquage `KeyPatternMasker`) et un adaptateur Filament mince (`ConfigViewerPlugin`, `ConfigViewerPage`). La page est en lecture seule, dans le groupe « Paramètres », réservée aux super administrateurs. Les commentaires du paquet sont en anglais.
- **Motif** : la configuration contient des secrets et des réglages d'infrastructure ; le masquage se fait dans le cœur, donc aucun adaptateur (page, API, console) ne reçoit une valeur masquée. Les valeurs sont lues dans le dépôt de configuration (la configuration effective), les fichiers servent seulement à dire d'où vient un groupe.
- **Portée** : couvre la consultation de la configuration. Pas de modification, pas d'affichage d'une valeur masquée, pas de variable `.env` brute. Les commentaires en anglais ne valent que pour le paquet ; le reste du projet garde les siens en français.
- **Corollaires** : une valeur sensible se masque en ajoutant un motif à `config-viewer.mask` (dernier segment de la clé ou clé complète) ; seules les chaînes non vides sont masquées. Un module dont le nom recoupe une clé de l'application (`Auth` → `auth`) forme un seul groupe aux deux origines. Les tests du cœur (suite `Packages`) tournent sans application ; ceux de la page sont dans `tests/Feature/ConfigViewerPageTest.php`. Ouvrir la page à un autre rôle demanderait une permission déclarée dans `PermissionEnum`.
- **Tranché par** : humain (demande) ; orchestrateur (accès super administrateur, masquage)
