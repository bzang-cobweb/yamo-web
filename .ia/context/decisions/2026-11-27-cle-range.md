# `2026-11-27` — Une seule clé `range` pour les bornes d'un champ

- **Type** : décision
- **Question posée** : « clé commune range », après « pourquoi ajouter un nouveau champ rating ? utiliser le même champ » et « c'est une range avec incrément 0.1 pourquoi l'appeler date_range ? ».
- **Ce qui est retenu** : la description d'un champ envoyée à l'app porte ses bornes dans une seule clé, `range: { min, max, step }` : une date (`AAAA-MM-JJ` ou `null`, `step` à `null`), une note (nombres, `step` l'incrément) ; `null` pour un autre champ. `date_range` disparaît, `stars` est une clé à part (note seulement). L'app lit `range` pour les deux calendriers de date (`dateBound`) et pour la note.
- **Corollaire** : un autre champ borné (un nombre, un intervalle) reprendra `range` au lieu d'une clé nouvelle.
- **Tranché par** : humain
